# Workspace Removal Spec — Canvas 2.0

**Goal:** Remove the entire workspace abstraction. Everything becomes user-level.
Messages grouped by `session_id`. Files, tools, skills, subagents — all global to the user.

---

## Design

### What disappears
- No `workspace_id` on any API endpoint, tool, storage call, or data path
- No workspace CRUD (create/delete/switch/list workspaces)
- No workspace-scoped capabilities/scoping (tools, skills, subagents always available)
- No workspace file cache / sync
- No workspace tabs in Flutter UI

### What replaces it
- `session_id` — groups conversation messages (generated by client, passed with every message)
- User-level file directory — `{root}/Files/` instead of `{root}/Workspaces/{id}/Files/`
- User-level directories for skills, subagents, memory, tools (already exist, workspace variants removed)
- Global tool/skill/subagent availability — no per-workspace enabled/disabled

### What stays the same
- `user_id` — user identity (default_user for single-user mode)
- SDK tools — same names, same signatures, just without workspace_id
- Tool implementations — same logic, paths resolved from user-level DataPaths
- Message persistence — same CoreMem/MessageStore, just keyed by session_id not workspace_id

## Layer 2: Message Storage (`src/storage/messages.py`)

### CoreMem integration — key insight

CoreMem is **metadata-agnostic**. It stores messages with arbitrary metadata fields and filters work on any field. No changes needed to the CoreMem library itself.

**One DB per user, not per workspace.** Currently:
- Personal workspace: `{root}/Conversation/` (user-level path) — stays
- Other workspaces: `{root}/Workspaces/{id}/` — removed

After removal, always use `{root}/Conversation/app.db`. Existing personal workspace data is already at the right path. Data in `{root}/Workspaces/{id}/` will be orphaned (see migration note).

**`observation_kwargs` change:** Currently passes `{"session_id": workspace_id}` to CoreMem's observer/reflector pipeline. After removal, we have one DB with all sessions. Options:
- **Recommended:** Drop `observation_kwargs` entirely — observer sees all user messages (user-level knowledge)
- Alternative: Keep one observer per session (complex, unnecessary)

### `MessageStore`
```python
# Before
class MessageStore:
    def __init__(self, user_id, base_dir=None, workspace_id="personal"):
        self.workspace_id = workspace_id
        if workspace_id == "personal":
            base_path = paths.conversation_dir()
        else:
            base_path = paths.workspace_conversation_path().parent
        ...
        self._core = MemoryCore(path=str(base_path), observation_kwargs={"session_id": workspace_id})

# After
class MessageStore:
    def __init__(self, user_id, base_dir=None):
        base_path = base_dir or paths.conversation_dir()
        ...
        self._core = MemoryCore(path=str(base_path))  # no observation_kwargs filter
```

### Methods

| Method | Before | After |
|--------|--------|-------|
| `add_message(role, content, metadata)` | metadata gets `workspace_id` injected | metadata gets `session_id` injected (caller-supplied) |
| `get_messages_with_summary(limit, workspace_id)` | Filters by `metadata.workspace_id` | Filters by `session_id` param |
| `get_recent_messages_for_workspace(ws_id)` | `metadata.workspace_id` query | Rename: `get_recent_messages_for_session(session_id)` |
| `delete_messages_for_workspace(ws_id)` | SQL: `$.workspace_id` | SQL: `$.session_id` |
| `observation_kwargs` | `session_id=workspace_id` | Remove (no per-session filter) |

### `get_message_store()` factory
```python
# Before: cache key = f"{user_id}:{workspace_id}:msgstore"
# After:  cache key = f"{user_id}:msgstore"  # one DB per user
```

### SQL changes
```sql

-- After

```

## DB Migration Concerns

### `work_queue.db` schema change
Currently has `workspace_id TEXT NOT NULL DEFAULT 'personal'` with index `idx_wq_workspace`.
**Migration needed**: alter table to drop column, drop index.

```sql
-- Migration for existing work_queue.db
DROP INDEX IF EXISTS idx_wq_workspace;
CREATE TABLE work_queue_new (
    id TEXT PRIMARY KEY,
    parent_id TEXT,
    user_id TEXT NOT NULL,
    agent_name TEXT NOT NULL,
    task TEXT NOT NULL,
    status TEXT NOT NULL,
    progress TEXT,
    config TEXT,
    instructions TEXT,
    cancel_requested INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);
INSERT INTO work_queue_new SELECT
    id, parent_id, user_id, agent_name, task, status, progress,
    config, instructions, cancel_requested, created_at, updated_at
FROM work_queue;
DROP TABLE work_queue;
ALTER TABLE work_queue_new RENAME TO work_queue;
```

Or use migration framework if one exists (check `WorkQueueDB._migrate()`).

### Orphaned workspace data
- Files in `{root}/Workspaces/{id}/Files/` → not migrated (user can copy manually)
- Conversation DBs in `{root}/Workspaces/{id}/app.db` → orphaned (main data stays in `{root}/Conversation/app.db`)
- Skills in `{root}/Workspaces/{id}/Skills/` → log migration notice, leave files

## Migration Order

1. **DataPaths** — remove workspace methods, add `user_files_dir()`, simplify `get_paths`
2. **Storage** — messages.py session-based storage, remove workspace from work_queue (with DB migration)
3. **SDK** — remove workspace from loop, runner, tools, coordinator, research, skills registry, custom tools
4. **HTTP** — remove workspace routers, retool conversation/websocket/memories handlers
5. **Config** — remove `workspace_root` from settings
6. **Delete** — delete workspace-specific files, capabilities.py, item_scopes.py, and test files
7. **Flutter** — remove workspace provider, retool all agents/services
